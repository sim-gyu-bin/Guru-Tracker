---
name: scheduled-sync
description: Supabase Cron과 접근 대체 경로가 같은 안전한 동기화 조정자를 호출하는 절차
---

이 스킬은 공식 출처 수집을 실행하는 모든 진입점에 적용한다. 스케줄러와 사용자 접근은 서로 다른 수집기를 만들지 않는다.

1. Supabase Cron의 `pg_cron`과 `pg_net`이 보호된 Next.js 내부 동기화 엔드포인트를 매시간 한 번 호출한다. 엔드포인트 비밀값은 Supabase Vault와 서버 전용 설정에만 두며, Vercel Hobby Cron을 사용하지 않는다. Supabase Edge Function은 구현 근거가 생기기 전까지 요구하지 않는다.
2. 스케줄 호출과 사용자 접근 경로는 같은 멱등 동기화 조정자와 DB lease를 사용한다. lease를 얻지 못한 호출은 중복 수집·회전을 하지 않는다.
3. 사용자 접근에서는 캐시를 먼저 반환한다. 캐시가 오래됐거나 스케줄 작업이 뒤처진 경우에만 같은 조정자를 요청하며, 초기 화면을 수집 완료까지 막지 않는다.
4. 조정자는 공식 원문 검증과 실제 변경 판정을 마친 뒤에만 현재/직전 두 스냅샷을 원자적으로 회전하고 dataset version을 증가시킨다. 실제 변경 이벤트에는 event/document 고유 키를 부여한다.
5. 커밋된 변경 이벤트만 알림 outbox에서 처리한다. outbox는 event/document 고유 키로 멱등하게 기록하고, 전송 실패가 원본 데이터 transaction을 되돌리지 않게 한다. 전달 완료 outbox와 이벤트 이력은 짧은 보존 기간으로 정기 정리하며, 정확한 기간은 운영 결정으로 남길 수 있다.
