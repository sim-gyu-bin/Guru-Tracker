name: project-brainstorm
description: Guru Tracker의 새 기능이나 기능 변경의 제품 범위를 설계할 때 사용한다.
---

기능 설계 전 제품 범위와 현재 저장소 상태를 확인한다. 구현된 기능과 계획을 구분하고, 새로운 추상화나 범위 밖 기능을 먼저 제안하지 않는다.

1. 사용자가 보는 문제와 일곱 추적 대상 중 관련 대상을 명확히 적는다.
2. `.omp/RULES.md`의 공식 출처·공개 한계가 이번 기능에 미치는 영향을 확인한다.
3. 동기화가 관련되면 캐시·진입점·저장 경계를 정하고, 구현 계약은 `scheduled-sync`를 따른다.
4. UI·API·DB·Storage·Wiki 중 필요한 경계만 적고, 불확실한 점은 결정된 사실처럼 쓰지 않는다.
5. 변경 후 실제 사용 경로로 검증할 방법을 정한다.

변경 알림이 관련되면 `web-push`를 참고해 구독·전송·실패 경계를 정한다. 관련 없는 기능에 동기화·알림 설계를 강제하지 않는다.
