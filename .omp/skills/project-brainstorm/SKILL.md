---

기능 설계 전 제품 범위와 현재 저장소 상태를 확인한다. 구현된 기능과 계획을 구분하고, 새로운 추상화나 범위 밖 기능을 먼저 제안하지 않는다.

1. 사용자가 보는 문제와 일곱 추적 대상 중 관련 대상을 명확히 적는다.
2. 공식 출처의 보고 주기·지연·공개 한계를 확인한다. 13F는 실시간이 아니며, ARK의 접근 공백 일별 이력은 재구성할 수 없고, Burry 옵션 손익은 정확히 알 수 없다.
3. 매시간 Supabase Cron과 오래된 캐시·뒤처진 스케줄에서의 접근 대체 경로가 같은 멱등 동기화 조정자·DB lease를 쓰고, 캐시 우선 화면·변경 문서만 수집·검증 뒤 원자적 두 스냅샷 교체를 지키는 최소 계약을 정한다.
4. UI·API·DB·Storage·Wiki 중 필요한 경계만 적고, 불확실한 점은 결정된 사실처럼 쓰지 않는다.
5. 변경 후 실제 사용 경로로 검증할 방법을 정한다.

변경 알림이 필요하면 커밋된 실제 변경 이벤트의 event/document 고유 키 outbox만 표준 Web Push(VAPID)로 전송하고, 사용자 제스처 opt-in·iOS 홈 화면 PWA 설치·짧은 보존 기간을 계약에 포함한다. 전송 실패는 원본 데이터 변경을 되돌리지 않는다.

사용자 문구는 한국어로, 구조와 코드 식별자는 영어로 쓴다.
