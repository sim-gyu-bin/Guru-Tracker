---
name: source-verification
description: 공식 원문을 증거로 검증하고 변경을 안전하게 반영하는 공통 절차
---

모든 수집 작업에서 공식 원문을 최우선 증거로 사용한다. 검색 결과, 뉴스, 제3자 재배포·집계는 발견용 단서일 뿐 원문을 대체하지 않는다.

1. 원문 URL, 발행 기관, 문서 식별자, 기준·보고·제출 시점을 기록한다.
2. 대상 인물과 문서 종류가 맞는지 확인한다. 13F는 다섯 기관 관리자, ARK 자료는 Cathie Wood, 하원 PTR은 Nancy Pelosi에만 연결한다.
3. 필요한 핵심 필드를 원문에서 확인하고, 불완전·모순·접근 실패를 검증 통과로 처리하지 않는다.
4. 이전 현재 스냅샷과 비교해 실제 변화만 판정한다.
5. 검증된 새 자료가 있을 때만 현재와 직전 두 스냅샷을 원자적으로 교체한다. 변화가 없으면 dataset version을 증가시키지 않는다.

Supabase Cron의 `pg_cron`과 `pg_net`이 보호된 Next.js 내부 엔드포인트를 매시간 호출하고, 사용자 접근은 캐시를 먼저 제공한 뒤 오래됐거나 스케줄 작업이 뒤처진 경우에만 같은 멱등 동기화 조정자를 요청한다. 두 경로는 같은 DB lease를 사용하며, Vercel Hobby Cron을 사용하지 않는다. 검증 transaction은 실제 변경이 있을 때만 두 스냅샷 회전·dataset version·event/document 고유 키 변경 이벤트를 기록한다. 커밋된 이벤트의 outbox만 전송하고, 전달 outbox와 이벤트 이력은 짧은 보존 기간 후 정리한다. 런타임 공시 파일은 Supabase Storage에 보관하고 `.wiki/raw`에는 넣지 않는다. 검증 결과에는 원문, 확인 항목, 변화 판정, 한계와 보류 이유를 명확히 쓴다.
