# Wiki 운영 지침

## 소유권과 계층

`.wiki/`는 저장소의 LLM Wiki 경계다. 파일은 다음 세 계층으로 관리한다.

1. **`.wiki/raw/` — 불변 원본 증거:** 사람이 소유한다. 세션 캡처, 외부 문서의 대표 샘플, 확인 가능한 관찰을 원문 언어와 맥락으로 보존한다. 기존 원본을 LLM이 재작성·정리·삭제하지 않는다. 정정은 새 보정 기록을 추가하고 원본을 가리킨다.
2. **`.wiki/wiki/` — LLM 소유 종합:** 영어로 작성한다. 원본 증거를 요약·연결하는 지식 페이지이며, 구현되었다고 주장하지 않는다. LLM은 이 계층을 갱신할 수 있다.
3. **인덱스와 로그:** `.wiki/wiki/index.md`는 모든 Wiki 페이지와 원본·운영 문서의 위치를 찾을 수 있게 유지한다. `.wiki/wiki/log.md`는 날짜순 추가 전용 변경 기록이다. 과거 로그 항목을 고치거나 재정렬하지 않는다.

## 증거와 추적성

- 종합 페이지의 사실 주장에는 `## Sources`에서 `.wiki/raw/`의 구체적 파일 링크를 둔다.
- 원본이 없는 외부 사실, 수집 결과, 런타임 데이터가 확보된 것처럼 쓰지 않는다.
- 원본의 언어는 보존한다. 초기 지식 페이지의 종합 언어는 영어다.
- 페이지 사이에는 상대 Markdown 링크를 사용한다. 링크 대상이 없는 이름만 나열하지 않는다.

## Wiki 페이지 형식

`.wiki/wiki/`의 종합 페이지는 YAML frontmatter에 최소 `title`, `status`, `source_capture`, `updated`를 둔다. 본문에는 다음을 명확히 구분한다.

- `## Decided facts`: 현재 증거로 확정된 내용
- `## Deferred / open questions`: 아직 결정·검증되지 않은 내용
- `## Sources`: 원본 캡처 링크

짧고 증거 우선으로 쓴다. 결정의 근거, 제한, 다른 페이지와의 관계를 링크로 남긴다.

## 정정 절차

1. 사람은 `.wiki/raw/`에 날짜가 있는 보정 또는 새 세션 캡처를 추가한다.
2. 해당 종합 페이지는 새 증거를 인용하여 갱신하고, 무엇이 바뀌었는지 `log.md` 끝에 추가한다.
3. 영향을 받은 인덱스 항목과 내부 링크를 갱신한다.
4. 이전 증거를 덮어쓰거나 사실처럼 추정으로 채우지 않는다.

## 안전과 범위

비밀값, 토큰, 개인 식별 정보, Supabase/Vercel의 런타임 덤프, 운영 중 내려받은 공시 원문을 이 디렉터리에 넣지 않는다. 런타임 공시 파일은 Supabase Storage에만 둔다. `.wiki/raw/`에는 향후 개발용 대표 샘플만 사람이 의도적으로 추가할 수 있다.
